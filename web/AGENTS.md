## Grindylocks web admin

The web admin for role holders (Rachel, city admins, park admins) and, since Nov 6, the teams that run brand, shop and organizer pages. It's its own npm project inside the app's repo, with its own lockfile: run npm commands from `web/`. The repo root's AGENTS.md (branches, pull requests, tokens) applies here too.

- **Two sites, one app (Nov 2):** `src/proxy.ts` serves the public marketing page (`src/app/site`) at `/` on grindylocks.com, sends www to the bare domain and any other path there to admin.grindylocks.com. Every other host is the admin, where `/site` stays public so previews can show it. Host rules live in `src/lib/hosts.ts`. Only grindylocks.com is indexable (`next.config.ts`).
- **The queue** (`src/app/(admin)/queue`, Nov 2): the URL holds the state (`?tab=`, `?area=`, `?item=`), the list and detail pane share one page, and every action is a Server Function in `actions.ts` that calls a moderation function (`moderate_reports`, `review_park_info`, `review_obstacle`). Reads live in `src/lib/queue.ts`. Keyboard: j/k, Enter, Esc, ?, and per-pane d/h/e/a/x, each opening its confirmation.
- **Public park pages (Nov 6):** `/parks` (every city), `/parks/<metro>` and `/park/<slug>` on grindylocks.com, built from `src/app/site/parks` and `src/app/site/park`. `SITE_SECTIONS` in `src/lib/hosts.ts` maps the public prefixes to those routes on every host (so previews work at the public paths too); `sitemap.xml` and `robots.txt` are served everywhere. Data comes only from the signed-out functions `public_metro_areas`, `public_metro`, `public_park` and `public_sitemap` through the cookie-less client (`src/lib/public-parks.ts`, cached with `cacheLife("hours")`). Nothing people-shaped goes on these pages. "Open now" runs in the browser (`src/components/public/open-now.tsx`). The share image is a route handler (`park/[slug]/share-image`) drawn with Archivo Black from `assets/`. The map is OpenStreetMap tiles with no library (`src/components/public/static-map.tsx`); swap its tile URL if traffic grows.
- **Brand and shop web tools (Nov 6):** `/manage/<handle>/details|location|hours|brands|team|inbox` (`src/app/(admin)/manage/[handle]`), listed under **Your pages** in the sidebar for anyone on a page's team; the tape reads PAGES for people with no admin role. `src/lib/page-sections.ts` says which sections a page has and which roles can use them (staff see locks); reads are in `src/lib/page-tools.ts` (server only) with limits in `page-fields.ts`; writes are Server Functions in `actions.ts` calling the same Postgres functions as the app's Edit page, Team and Inbox. Hours are edited one row per day and folded back into groups with the app's `page-hours.ts`. Find on the map calls Nominatim from our server only (`src/lib/geocode.ts`: one request a second, the app named, answers cached, only on the button); swap it with the tiles. The pin map (`src/components/pin-map.tsx`) reuses the public pages' tile code. Logos are cropped in the browser to 512 px PNGs (`src/lib/logo-png.ts`, shared with Send claim invite). The Inbox is read-only.
- **Shared copies (Nov 6):** `src/lib/hours.ts` and `src/lib/page-hours.ts` are byte-for-byte copies of the app's, and `src/lib/obstacle-types.ts` holds the app's English obstacle names, so the web stream never edits `src/`. `npm run check:shared` fails if any of them is stale.
- **The request form** calls `request_access()` through a cookie-less client (`src/lib/supabase/public.ts`), so it always asks as a signed-out visitor. Requests are readable only by the owner (table `access_requests`).
- **Local builds without Google Fonts** (sandboxes): `NEXT_FONT_GOOGLE_MOCKED_RESPONSES=<mock.js> npx next build --webpack`. Vercel fetches the real fonts. The `--webpack` build doesn't run Tailwind (its loader is set up for Turbopack), so it proves compilation only; for screenshots, compile `globals.css` with `@tailwindcss/node` and swap it in.

- **Stack:** Next.js 16 (App Router, Cache Components), Tailwind v4, shadcn/ui on Base UI. shadcn components are copied into `src/components/ui/` and restyled to `design/web.md`; swap their Lucide icons for `<Icon>` (Material Symbols Sharp).
- **Design tokens:** `src/styles/tokens.css` is generated from `design/tokens.json` by `npm run tokens` at the repo root. Never edit it by hand. `src/app/globals.css` maps the tokens into Tailwind (`bg-gl-surface`, `type-title`) and shadcn's names.
- **Database types:** `src/lib/database.types.ts` is a copy of the app's, written by `npm run db:types` (or `npm run sync:db-types`) at the repo root; `npm run check:db-types` fails if they differ. Never edit it here.
- **Auth:** Supabase email codes with `@supabase/ssr` cookies and `shouldCreateUser: false`, so the web can't create accounts. `src/proxy.ts` refreshes the session and sends signed-out visitors to sign-in. In `src/lib/admin.ts`, `getViewer()` is the door (an admin role or a page team, via `my_pages()`; anyone else goes through `/sign-out?reason=no-access` to "Nothing to run here"), and `getAdmin()` is the role check that admin pages and their Server Functions keep using. Page sections check `getMyPage(handle)`.
- **No service-role key, ever.** Reads and writes use the signed-in admin's own session, so the database's access rules apply exactly as in the app. Moderation actions are Postgres functions both apps call; no moderation logic lives here.
- **Cookie reads sit behind `<Suspense>`** (Cache Components): see `src/app/(admin)/layout.tsx`.
- **English only.** Copy follows the app's voice: plain, sentence case, no exclamation marks.

Checks before a PR, from `web/`: `npm run typecheck`, `npm run lint`, `npm run check:shared`, `npm run build`.
